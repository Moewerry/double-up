# DoubleUp

薄荷绿、奶油白与珊瑚红配色的数字滑动解谜游戏，适配手机与桌面。第一章包含 30 个固定布局关卡，通关后顺序进入下一关。

当前关卡与参考解法已经配置，尚待所有者执行回放、测试和人工试玩。难度节奏仍需根据试玩调整。

## 运行与验证

使用 Node.js 22.12+，建议 Node.js 24 LTS。

```powershell
npm ci
npm run dev
```

由所有者按需执行检查与构建。

```powershell
npm run typecheck
npm run test:run
npm run levels:verify
npm run build
```

`npm run levels:verify` 使用正式引擎逐关执行配置中的参考方向序列，检查每一步有效、最终通关和回放结果一致。遇到失败会停止。它不判断参考解法是否最短，也不代替人工试玩。

如需导出并复核完整回放，可以执行以下命令。

```powershell
npm run levels:verify -- --write
npm run levels:replay
```

只有全部关卡的参考解法通过后，才会写入 `scripts/level-replays.json`。回放包括数字棋盘、开门状态和坍塌状态。修改关卡布局或规则后需升级该关配置版本，并重新生成回放。

## 关卡设计

- 第 1–6 关学习滑动、全盘移动、隔空合并、单步只合并一次和墙体阻挡。第一关直接显示手势，第二关停留 2.5 秒后显示手势。
- 第 7–10 关利用墙体定位、绕路和会合，第 10 关安排一次滑动完成两组合并。
- 第 11–15 关加入终点，练习合并位置、运输和绕行。
- 第 16–20 关加入数字锁门，逐渐组合钥匙制造、开门和运输。
- 第 21–30 关加入一次性地板，再组合墙体、终点和锁门，第 30 关完成第一章。

逐关标题、棋盘、提示和参考解法位于 `src/game/level-designs.ts`。每行使用四个以空格分隔的格子，四行组成棋盘。

- `.` 为空地，`#` 为墙，数字为初始方块。
- `G` 为终点，需要精确送入本关目标数字。
- `K8` 为需要消耗一个 8 的锁门，其他数字锁门使用相同格式。
- `F` 为一次性地板。需要在初始数字下放置地板时，用 `fragile` 配置格子编号，编号从左上角 0 到右下角 15。

## 规则与操作

手机在棋盘上滑动，桌面使用方向键或 WASD。设置左侧的键盘图标打开操作指南。

所有数字一起移动，相同数字相遇时合并，每个数字单步只合并一次。每关开局固定，移动后不生成新数字，通关不限步数，无效移动不计步。

墙和已坍塌的地板阻挡移动。数字朝锁门滑动时，数值相同就会被门消耗并打开门。刚合成的数字先停下，需要下一次滑动才能开门。同一次滑动中，其他数字仍把刚打开的门视为障碍，从下一次滑动起可以穿过。

数字经过并离开的一次性地板，在整次滑动结束后坍塌。跨过的地板也会坍塌，仍有数字停留的地板保持完整，之后离开才坍塌。一次滑动中，多个数字可以经过尚未坍塌的同一格。

数字合并关达到目标即通关，开门关需要打开所有门，运输关需要打开所有门并把精确数值送入终点。数字被挡住而无法移动，或剩余可用数字总量不足以完成目标时失败。某些走错路线的局面可能仍能移动，可通过设置中的重新开始恢复原布局。

重新开始会复原数字、门、地板、分数和步数。首页的独立互动教程共享滑动逻辑，使用教学预设且不生成新数字，最后练习正式第一关。教程不改写正式闯关进度。

## 存档

localStorage 使用 `double-up:save:v1` 保存局面、机关状态、通关记录和设置。每次有效移动一次写入完整状态，刷新后恢复当前局面。内部撤销快照也包含门和地板，界面保持通过重新开始重试的操作方式。

本次固定解谜关卡的配置版本为 10。旧版随机关卡的记录与音乐、音效设置保留，新版解锁及成绩按当前关卡版本计算，因此旧版玩家从新版第一关开始。旧记录会在相应关卡首次完成新版挑战后更新。

损坏或配置过期的当前局面会准备新版待挑战关卡。未知存档格式暂停输入，多标签页改写后需要刷新读取最新存档。存储异常时提供重试保存。

当前局面自动恢复或关卡配置更新时直接进入可玩的关卡。设置中的“清空游戏数据”经过确认后，会重置此浏览器中的进度、成绩和游戏设置，并返回首页。清空结果保存失败时保留原有数据，可在确认弹窗中重试。

- [游戏地址](https://moewerry.github.io/double-up/)
- [部署记录](https://github.com/Moewerry/double-up/actions/workflows/deploy-pages.yml)

通用组件使用 shadcn/ui，布局使用 Tailwind CSS 4，棋盘和机关为游戏专有展示组件。
