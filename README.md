# DoubleUp

奶油蜜桃色的数字合并游戏，适配手机与桌面。只有首页和关卡页，从当前关开始，通关后顺序进入下一关，没有选关入口。

当前是前 5 关开发预览，配置与交互尚待运行验证，不代表 20 关正式版。后续关卡没有作为可解锁内容发布。

关卡配置已统一包含稳定 ID、配置版本和类型：第 1、2、5 关为“数字合并”，第 3、4 关为“布局练习”。两种类型共用当前的滑动合并规则，布局练习强调空位与大数字摆放，并非新增的特殊方块机制。类型定义位于 `src/game/level-types.ts`，页面直接读取配置中的类型。

## 环境与命令

Node.js 22.12+，建议 Node.js 24 LTS；npm，依赖版本记录在 package-lock.json。

```powershell
cd double-up
npm ci
npm run dev
```

由项目所有者按需执行检查和构建：

```powershell
npm run typecheck
npm run test:run
npm run build
npm run preview
```

本地不自动启动项目或执行编译、构建、语法检查及测试；部署构建由 GitHub Actions 执行。规则与存档回归用例由所有者执行 `npm run test:run`，覆盖四向合并、禁止重复合并、无效操作、胜负优先级、撤销与随机流复现、存档恢复以及保存失败重试。

## 操作

- 手机在棋盘上滑动；桌面使用方向键或 WASD。设置左侧的键盘图标打开操作指南弹窗，对局底部不显示方向按钮。
- 相同数字相遇时合并，每个方块单步只合并一次；无效移动不计步、不生成方块。
- 进行中的对局通过设置里的“重新开始”重开，界面不提供撤销入口。重开恢复固定初始局面，历史通关纪录保留。
- 首页恢复当前局面，通关后通过结果弹窗进入下一关。第五关显示预览章节完成，可重玩本关。
- 音效默认关闭，可在设置中开启。
- 关卡页顶部仅显示目标数字，统计区保留本局得分、已走步数和通关最高分，合并时反馈新增分数。通关结算分别显示首次通关、最高分和最少步数的新纪录。
- 多指操作、取消手势和切到后台不会提交该次手势，设置、操作指南、重开确认和结算弹窗期间暂停输入。关闭操作指南后，焦点返回棋盘；系统开启减少动态效果时直接呈现新局面。

## 存档

localStorage 使用 `double-up:save:v1` 单键原子写入局面、撤销快照、通关记录与设置。有效移动先保存逻辑结果，再展示动画。存档仅限当前浏览器与站点，多标签页改写后暂停输入，需要刷新读取最新进度。

不兼容版本不会自动覆盖；损坏的当前局面重新开始，尽可能保留连续有效的历史纪录。存储异常时提供“重试保存”，成功保存后清除失败提示；对局页面不展示常驻的保存说明。

## 关卡通关路径

当前 5 关仍为待验证配置，没有随本次改动提供已经执行通过的通关路径。以下命令必须由所有者运行：

```powershell
npm run levels:verify -- --write
npm run levels:replay
```

第一条命令使用正式引擎和固定随机种子搜索路径，并从正式初始状态重新回放；仅在全部关卡通过后写入 `scripts/level-replays.json`。记录包括配置版本、目标、种子、方向序列、分数、步数、最大数字、随机状态和最终棋盘。第二条命令读取已保存的记录并复核，配置变化或结果不一致时失败。

搜索每关最多展开 200,000 次方向操作，保留 96 个候选状态，最多搜索 600 步；找不到路径会停止并保留原回放文件，不据此断言关卡无解。找到一条通关路径也不代表所有走法都可通关，正式发布前仍需人工评估难度。本次未运行这些命令、未生成回放文件、未标记关卡已经验证。

## 验收与部署

需人工验证四向移动、一次合并规则、无效输入、撤销后相同方向复现、刷新恢复、顺序闯关、结算关闭后重新查看、多指手势、快速输入及 320–430px 手机布局。前 5 关需通过正式引擎回放与人工试玩验证后，才能作为正式关卡发布。

自动部署使用 GitHub Pages。每次推送到 `main`，`.github/workflows/deploy-pages.yml` 会在 GitHub Actions 上安装依赖、构建并发布 `dist`；也可以在 Actions 页面手动运行该工作流。本地无需先构建，不提交 `dist`。

- 发布地址：[DoubleUp](https://moewerry.github.io/double-up/)。
- 部署进度与失败日志：[GitHub Actions](https://github.com/Moewerry/double-up/actions/workflows/deploy-pages.yml)。
- 仓库 [Settings → Pages](https://github.com/Moewerry/double-up/settings/pages) 的 Source 使用 **GitHub Actions**。

工作流使用 Node.js 24 和 `npm ci` 安装锁定依赖，再执行 `npm run build`。构建时从 Pages 读取站点子路径并传给 Vite `--base`，适配 `/double-up/`，本地开发仍使用默认根路径。使用 HashRouter，无需额外配置页面路径回退。构建成功后才会进入部署任务。

通用组件来自 [shadcn/ui 官方注册表](https://ui.shadcn.com)，布局使用 Tailwind CSS 4。棋盘与数字方块是游戏专有展示组件。
